# Nikki Desktop 设计说明

日期：2026-08-30

## 目标

最终目标是一个不依赖 Wallpaper Engine 的 Windows 10 动态桌面播放器（B）：界面位于桌面图标后方，能够播放本地音乐、显示封面与歌词，并可从系统托盘退出或切回普通窗口。

第一里程碑先交付普通独立窗口（A），用来证明原网页播放器能够脱离 Wallpaper Engine 正常加载、播放和读取歌词。A 与 B 共用同一套网页内容和 WebView2 宿主，避免做两套播放器。

## 已选方案

- Windows 宿主：.NET 8 WinForms。
- 网页运行环境：Microsoft Edge WebView2；本机已安装 WebView2 Runtime。
- 内容加载：把网页目录映射到一个 HTTPS 虚拟域名，避免直接打开 `file://` 时歌词 `fetch()` 被浏览器拦截。
- Wallpaper Engine 兼容层：在网页脚本运行前注入必要的 `wallpaper*` 接口；音频频谱优先从页面自己的音频元素采集，不依赖 Wallpaper Engine 的系统音频回调。
- A 模式：普通可关闭、可缩放窗口。
- B 模式：把同一个窗口挂到 Explorer 的桌面 WorkerW 层，铺满所选显示器；系统托盘提供退出、重新嵌入和切回窗口模式。

## 目录与资源边界

- 新项目独立放在 `outputs/NikkiDesktop`，Steam Workshop 原目录保持只读。
- 参考播放器通过导入脚本复制到 `content/reference-player`，运行时不再依赖 Steam 或 Wallpaper Engine。
- `content/`、编译产物和 WebView2 用户数据不进入普通 Git 历史，避免把约 621 MiB 的音乐与图片永久写入每一个 Git 克隆。
- Git 保存源代码、测试、导入脚本、资源清单和说明文档。将来上传时，再由用户决定：私有仓库加 Git LFS、单独 Release 压缩包，或仅发布不带版权素材的程序。

## 版权与发布

参考播放器的程序源代码来自 OriginalCube/Bocchi-Wallpaper（MIT），但其中的动画、封面、音乐和歌词不因此自动获得再发布许可。本地自用测试可以完整复制；如果公开给别人试用，应把程序与内容包分开，默认让用户导入自己合法持有的素材。

暖暖主题将作为后续内容包制作，不和宿主程序耦合。这样可以替换图片、音乐、歌词和配色，而不必改动桌面嵌入代码。

## 安全与恢复

- 不注入 Explorer 进程、不替换系统 DLL、不修改 Windows 系统文件。
- 桌面模式只使用公开 Win32 窗口关系与进程内 WebView2；退出程序后桌面恢复原状。
- 首版不设置开机自启。等普通窗口和桌面模式都验收后，再单独决定是否添加可撤销的自启选项。
- 任何嵌入失败都回退到普通窗口，不把程序留在不可见状态。

## 验收标准

1. 从新项目目录启动 A，不启动 Steam 和 Wallpaper Engine，也能打开完整播放器。
2. 歌曲可播放，封面可切换，LRC 歌词能读取且控制台无本地文件跨域错误。
3. B 能位于桌面图标后方；托盘菜单可以退出或恢复普通窗口。
4. 自检能明确报告 WebView2 Runtime、内容目录和必需文件的状态。
5. Git 历史中不含大体积媒体；从干净源码按 README 可重新导入并构建。

# 最大化暂停、模式勾选与启动播放设计

## 行为定义

其他程序成为前台窗口，并且处于 Windows 标准最大化状态或覆盖所在显示器完整边界时，播放器自动暂停。窗口恢复、关闭或用户回到桌面后，只恢复本次被自动暂停的音频；进入前已经手动暂停的音频仍不恢复。播放器自身窗口、Explorer 桌面与任务栏、隐藏、最小化和 DWM cloaked 窗口继续排除。

托盘菜单前两项固定为“切换-窗口模式”和“切换-桌面模式”。当前实际模式左侧显示勾，另一项不勾；二者始终互斥。桌面嵌入失败并回退窗口模式时，勾选状态必须跟随实际结果，而不是用户刚点击的目标。

页面加载成功后，宿主以 WebView2 用户手势级调用启动播放器当前默认歌曲。它等待播放器建立音频对象，恢复音频上下文并播放默认的非按键音音轨。成功与失败写入验收状态；普通使用时失败不弹窗、不崩溃，用户仍可手动点击播放。

## 结构

纯策略层给前台窗口上下文增加 `IsMaximized`，并把“全屏或最大化”统一判定为需要暂停。纯策略层另提供当前宿主模式到两个菜单勾选值的映射，WinForms 只负责应用映射。

应用层检测器用 `IsZoomed` 读取标准最大化状态。启动播放由独立服务通过 Chrome DevTools Protocol 执行异步脚本并解析结果，避免把脚本与表单生命周期混在一起。导航完成后先尝试自动播放，再启动前台窗口监视和截图验收。

## 验证

核心测试先证明任务栏仍可见的标准最大化窗口会触发暂停，并验证两种模式的互斥勾选。真实验收使用一个保留标题栏语义的最大化 WinForms 窗口，确认暂停一次、恢复一次。启动验收不再由截图流程主动点播，而是要求导航完成后的自动播放结果为成功、音频时间实际增长。最后重建完整包和 ZIP，并逐文件校验路径、大小与 SHA-256。

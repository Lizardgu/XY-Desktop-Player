# 全屏窗口自动暂停设计

## 用户交互

托盘右键菜单的前两项改为“切换-窗口模式”和“切换-桌面模式”。其余项目及顺序不变。“重新加载播放器”继续调用 WebView2 的 Reload，相当于刷新内部网页；用于页面卡住或素材文件变更后重建播放器，当前歌曲、进度和网页临时状态可能重置。

当其他程序的前台窗口覆盖其所在显示器的完整边界时，播放器自动暂停。前台窗口离开全屏、关闭或用户回到桌面后，程序只恢复由本功能暂停的音频；进入全屏前已手动暂停的音频不会恢复。窗口模式和桌面模式采用同一规则。

## 检测与状态

应用每 500 毫秒读取一次前台顶层窗口。检测器排除本进程窗口、Explorer 桌面层、任务栏、隐藏窗口、最小化窗口和 DWM cloaked 窗口；使用 DWM 扩展窗口边界，失败时回退到 GetWindowRect，再与 MonitorFromWindow 返回的完整显示器边界比较。边界允许 2 个物理像素误差，因此多显示器和无边框全屏可以工作，而保留任务栏的普通最大化窗口不会被判为全屏。

纯策略层只接收窗口状态与矩形，不调用 Win32，负责判定“其他全屏窗口”以及暂停/恢复状态转移。WinForms 控制器在 UI 线程计时，避免 WebView2 跨线程访问和重叠检查。

## 播放控制

进入全屏时，WebView 脚本收集当前正在播放、未结束的音频对象，保存对象引用后逐个 pause。退出全屏时只对这批仍存在、仍暂停且未结束的对象调用 play，然后清空保存集合。若进入全屏时没有播放中的音频，保存集合为空，因此退出后不会启动任何手动暂停的歌曲。

导航开始、表单关闭或 WebView 不可用时停止监视并清空状态。Win32 检测或脚本执行异常只记录错误并保持当前播放状态，不允许计时器异常终止进程。

## 验证

核心测试覆盖：全屏几何、多显示器坐标、任务栏间隙、本进程/桌面/隐藏/最小化/cloaked 排除，以及进入全屏暂停、持续全屏不重复切换、退出后按自动暂停状态恢复、手动暂停不恢复。最终在真实 Windows 桌面中用一个全屏测试窗口验证音频时间停止，关闭后继续增长，并重新生成完整包及 ZIP。

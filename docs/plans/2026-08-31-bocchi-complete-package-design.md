# “孤独摇滚壁纸移植”完整包设计

## 目标

把当前只能由开发者辨认的平铺式发布目录，整理成一个普通用户解压后即可使用的完整包。用户只需要看见一个明确的主启动入口；普通窗口保留为故障排查入口。发布名称、窗口标题、托盘文字和说明统一为“孤独摇滚壁纸移植”，不再在成品中出现 Nikki 命名。

本轮只制作包含现有 144 个播放器文件的完整包。可替换照片和音乐的空壳包留待用户验收完整包后再提炼，不提前扩展其导入协议或编辑界面。

## 已确认的故障

现有两个 `.cmd` 文件在工作区和发布目录中都是 LF-only。Windows 10 的 `cmd.exe` 运行后会吞掉后续行的首字符，导致 `cd`、`if exist`、`echo` 分别被解析成损坏的命令。现有包还故意排除了 `content\reference-player`，因此即使脚本换行正确也无法直接播放。

## 成品结构

```text
孤独摇滚壁纸移植-完整包\
├─ 双击这里-启动桌面壁纸.cmd
├─ 普通窗口（备用）.cmd
├─ 使用说明.txt
├─ app\
│  ├─ BocchiWallpaperPort.exe
│  └─ 程序运行依赖
└─ content\
   └─ reference-player\
      └─ 完整网页、照片、音乐与歌词
```

顶层只有三个用户文件和两个归类目录。主启动器使用桌面模式；备用启动器使用普通窗口。批处理正文只使用 ASCII 路径和文字，并由发布脚本显式写成 CRLF，避免依赖 Git 或本机代码页。两个入口都先检查程序和内容，再通过相对路径启动，所以整个文件夹移动、压缩和解压后仍可使用。

## 产品命名

WinForms 的窗口标题、托盘提示、错误框和退出菜单全部显示“孤独摇滚壁纸移植”。应用程序集名改为 `BocchiWallpaperPort`，核心程序集改为 `BocchiWallpaperPort.Core`；源代码命名空间和项目目录暂不做高风险的机械重命名，但发布成品里不留下 Nikki 文件名。

## 验证

发布回归测试必须实际生成临时完整包，并确认顶层结构、完整内容复制、无顶层 DLL、无 Nikki 文件名，以及两个批处理文件全部使用 CRLF。测试还会临时移走 `app` 目录，用真正的 `cmd.exe` 执行启动器并检查其返回码，确保脚本能被 Windows 正确解析。最终包再执行内容 SHA-256 清单、应用自检、真实桌面启动和压缩后解包检查。
